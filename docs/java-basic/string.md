# String


## String 为什么设计成 final 不可变的？

### 什么是不可变

- String 内部的字符数组 `private final char[]`（JDK 9 后是 byte[]）**私有且无修改入口**
- 所有"修改"操作（replace / concat / substring）都返回**新对象**，原对象永不被改

### 五大设计原因

| # | 原因 | 说明 |
|---|------|------|
| 1 | **字符串常量池的前提** | 常量池里多个引用指向同一个 String；若可变，一处修改全部遭殃——不可变才能安全共享，节省内存 |
| 2 | **hashCode 可缓存** | hash 计算一次缓存在字段里；HashMap 的 key 大量是 String，不可变保证 hash 稳定，定位桶永远正确 |
| 3 | **线程安全** | 不可变对象天然线程安全，无需同步，自由跨线程传递 |
| 4 | **安全性** | 文件路径、网络地址、类名、SQL 参数都是 String；可变的话传入后可能被偷偷改写（TOCTOU 攻击） |
| 5 | **安全模型基石** | 类加载器按名字缓存类；`java.lang.String` 若可被篡改/继承，双亲委派的安全模型就崩了 |

### JDK 9 的优化：Compact Strings（JEP 254）

| 项 | JDK 8 及以前 | JDK 9+ |
|----|--------------|--------|
| 内部存储 | 固定 `char[]`（UTF-16，每字符 2 字节） | `byte[]` + `coder` 编码标记 |
| 编码选择 | 无 | 内容全在 Latin-1 范围（英文数字符号）→ 1 字节/字符；含中文等 → 仍 2 字节 |
| 内存 | 英文字符串浪费一半 | 纯拉丁字符串**省 50% 内存** |

- 动机：堆中 String 占比最大，而绝大多数字符串只含 Latin-1 字符
- String 相关的 StringBuilder、StringBuffer 同步改造
- `coder` 字段参与 `hashCode` 计算，不同编码不会碰撞出相同 hash

### final 的两层含义

| 层面 | 含义 | 目的 |
|------|------|------|
| **类 final** | 不可被继承 | 防止子类改写行为，破坏不可变语义 |
| **字段 final + private** | 内部数组引用不可再指向别处，且外部拿不到 | 从源头上杜绝修改入口 |

::: info

追问点：① 大量拼接用 StringBuilder（不可变 String 循环 + 会产生大量临时对象）；② JDK 9 的 compact strings（char[] → byte[]，拉丁字符省一半内存）；③ 不可变带来的代价：每次"修改"都新建对象，用 Builder/池化缓解。
:::
