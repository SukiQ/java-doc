# MongoDB


## MongoDB 的特点和适用场景？

### 特点

| 特性 | 说明 |
|------|------|
| **文档模型** | BSON（类 JSON）存储，一条文档即可存对象/嵌套数组，**无需 JOIN 拆表** |
| **Schema 自由** | 同集合文档结构可不同，字段增删无需 DDL，**适合需求多变的业务** |
| **水平扩展** | 原生**分片**（Sharding），按 shard key 自动分散数据 |
| **高可用** | **副本集**（Replica Set）：一主多从，自动选主故障转移 |
| **查询能力** | 丰富查询 + 二级索引（B 树）+ **聚合管道**（类 SQL group by）+ 地理空间索引 |
| 事务 | 4.0+ 支持多文档 ACID 事务，但性能与能力仍弱于关系库 |

### 适用场景

| 场景 | 理由 |
|------|------|
| **弹性结构数据**：内容管理、商品属性（不同品类字段不同）、用户画像 | schema 自由，新增字段零成本 |
| **高写入吞吐**：日志、埋点、IoT 时序 | 写性能好，分片易扩 |
| **地理位置服务**：附近的人/门店 | 原生 2d/2dsphere 地理索引，一句查询搞定 |
| **中间结果/缓存态**：Feed 流、评论树 | 嵌套文档一次读出，免 JOIN |
| 大数据聚合分析 | 聚合管道 + 分片并行 |

### 不适用的场景

- 强一致性多表事务（转账类）→ 用 MySQL
- 复杂多表关联分析 → 关系库 / ClickHouse
- 纯 KV 缓存 → Redis 更轻

### 与 MySQL / Redis 对比

| 对比 | MongoDB | MySQL | Redis |
|------|---------|-------|-------|
| 模型 | 文档（BSON） | 关系表 | KV/结构 |
| Schema | 自由 | 严格 DDL | 无 |
| 事务 | 4.0+ 支持但弱 | 强 ACID | 弱（multi/exec） |
| 扩展 | 原生分片 | 分库分表改造 | 主从/集群 |
| 定位 | 灵活存储 + 查询 | 强一致业务数据 | 缓存/高速读写 |
